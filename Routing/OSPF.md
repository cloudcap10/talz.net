# OSPF — Open Shortest Path First

## 1) What is OSPF?

- OSPF is an Interior Gateway Protocol (IGP) used in IP networks.
- It is a **Link-State** routing protocol that uses **Dijkstra's SPF algorithm** to find the shortest path.
- It is **open standard** and protocol number is **89**.

---

## 2) How OSPF Works

- Routers discover neighbors using **Hello** packets.
- They build a **Link-State Database (LSDB)** of the area.
- LSDB is synchronized with all routers in the area.
- **SPF algorithm** is run to calculate the best path.
- Best paths are installed in the routing table.
- Updates are triggered on topology change only.

---

## 3) OSPF Characteristics

- Link-State Protocol
- Hierarchical Design (Area Based)
- Classless (CIDR / VLSM Support)
- Supports Authentication
- Fast Convergence
- Scalable and Efficient
- Uses IP Protocol 89
- Supports Equal-Cost Load Balancing (ECMP)

---

## 4) OSPF Network Types

| Type | Description |
|------|-------------|
| **Broadcast** | Default on Ethernet |
| **Non-Broadcast Multi-Access (NBMA)** | Frame Relay, X.25 |
| **Point-to-Point** | Direct link between two routers |
| **Point-to-Multipoint** | One router to multiple |

---

## 5) OSPF Areas & Hierarchy

- **Backbone Area**: Area 0 (Mandatory)
- Other areas connect to Area 0.

### Area Types

| Area Type | Description |
|-----------|-------------|
| **Standard Area** | Normal OSPF area |
| **Stub Area** | No external routes |
| **Totally Stubby Area** | Only default route |
| **NSSA Area** | Allows external routes (Type-7) |
| **Totally NSSA** | Only default route via NSSA |

> Smaller areas = Better performance.

---

## 6) OSPF Neighbor States

| State | Description |
|-------|-------------|
| **Down** | No Hello received |
| **Init** | Hello sent |
| **2-Way** | Bi-directional Hello received |
| **ExStart** | Master/Slave decided |
| **Exchange** | DBDs are exchanged |
| **Loading** | LSAs are requested |
| **Full** | LSDBs are synchronized |

---

## 7) OSPF Timers (Default)

| Timer | Default |
|-------|---------|
| **Hello Interval** | 10 sec (Broadcast) |
| **Dead Interval** | 40 sec (4× Hello) |
| **LSA Refresh Time** | 30 min |
| **LSA Max Age** | 60 min |
| **SPF Calculation Delay** | 5 sec |
| **SPF Hold Time** | 10 sec |
| **LSA Throttle Interval** | 5 sec |

---

## 8) OSPF Packet Types

| Packet | Purpose |
|--------|---------|
| **Hello** | Discover & maintain neighbors |
| **Database Description (DBD)** | Exchange LSDB summary |
| **Link State Request (LSR)** | Request specific LSAs |
| **Link State Update (LSU)** | Send LSAs |
| **Link State Acknowledgment (LSAck)** | Acknowledge LSAs |

---

## 9) OSPF LSA Types

| Type | Name | Description |
|------|------|-------------|
| Type 1 | Router LSA | Describes router's links within an area |
| Type 2 | Network LSA | Generated by DR on multi-access networks |
| Type 3 | Summary LSA | Inter-area routes (ABR generated) |
| Type 4 | ASBR Summary LSA | Path to ASBR |
| Type 5 | AS External LSA | External routes (ASBR generated) |
| Type 7 | NSSA External LSA | External routes in NSSA |

---

## 10) OSPF Route Types

| Route Type | Code | Description |
|------------|------|-------------|
| **Intra-Area** | O | Within the same area |
| **Inter-Area** | O IA | Between different areas |
| **External Type-1** | E1 | Cost includes internal + external |
| **External Type-2** | E2 | Cost includes external only |
| **NSSA External** | N1/N2 | External in NSSA |

### E1 vs E2

- **E1** (Type-1): Cost includes internal + external metric.
- **E2** (Type-2): Cost includes external metric only (default).

---

## 11) OSPF Cost Calculation

```
Cost = Reference Bandwidth / Interface Bandwidth
```

- Default Reference BW = **100 Mbps**
- Can be changed with `auto-cost reference-bandwidth` command.
- Lower cost = Preferred path.

---

## 12) OSPF Designated Router (DR) & Backup DR (BDR)

- On **multi-access** networks, OSPF elects DR and BDR.
- **DR** handles all LSAs and forms adjacencies with other routers.
- **BDR** is the standby router.
- Helps reduce LSA flooding and improves efficiency.
- **Point-to-Point** links do not have DR/BDR.

```
      Router A
         |
    Multi-Access Network
      /        \
Router B      Router C
  (DR)         (BDR)
```

## 14) OSPF Configuration (Cisco)

### Single Area (Area 0)

```
router ospf 1
 router-id 1.1.1.1
 network 192.168.1.0 0.0.0.255 area 0
 network 192.168.2.0 0.0.0.255 area 0
 passive-interface default
 no passive-interface g0/0
```

### Multi-Area (Area 0 and Area 1)

```
router ospf 1
 router-id 1.1.1.1
 network 30.0.0.0 0.0.0.255 area 0
 network 10.0.1.0 0.0.0.255 area 1
```

## 16) OSPF Advantages

- Open Standard
- Fast Convergence
- Efficient (Triggered Updates)
- Scalable (Area Based)
- Supports VLSM and CIDR
- Supports Authentication
- Load Balancing (ECMP)

---

## 17) OSPF Disadvantages

- Complex configuration
- Consumes more memory & CPU
- More bandwidth due to LSAs
- Not suitable for small networks
- Design and troubleshooting can be complex

---

## 18) OSPF Best Practices

- Use Area 0 as backbone and keep it stable.
- Keep area size small and summarize routes.
- Use stub areas to limit LSAs.
- Use passive interface on user-facing interfaces.
- Use authentication for security.
- Monitor OSPF regularly.

---

## 19) OSPF Troubleshooting Tips

| Issue | Check |
|-------|-------|
| Neighbor not forming | Check IP, Hello/Dead timers, Area ID |
| Adjacency stuck in ExStart | Check MTU mismatch |
| Routes not appearing | Check LSDB and area configuration |
| Slow convergence | Check for too many LSAs |
| Debug adjacencies | `debug ip ospf adj` for detailed logs |

## 21) OSPF Advanced Concepts

| Concept | Description |
|---------|-------------|
| **Virtual Links** | Connect non-backbone areas through another area |
| **Route Summarization** | Done at ABR to reduce routing table size |
| **Graceful Restart** | Helps in quick recovery after process restart |
| **Opaque LSAs** | Used for TE (Traffic Engineering) and Graceful Restart |
| **BFD with OSPF** | Provides fast failure detection |
| **OSPFv3** | Version of OSPF for IPv6 (uses IPv6 protocol 89) |

---

> **Tip:** Keep area design simple. Use summarization and authentication. Monitor LSDB and route table regularly for a healthy OSPF network.
